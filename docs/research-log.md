# Warabi Engine 研究ログ

かな漢字変換リランカーの開発記録。設計原則は architecture.md、現在状態は CLAUDE.md。
ここは「何を試し、何が効き、何が効かなかったか」の史料。

## 系譜(モデル世代)

```
LINE DistilBERT期 → 教師v1(LUW BERT) → 蒸留期 v1〜v5b → v6(空文脈KD) → v6b
                                                → v7(文節世代) → v8(語彙世代) ← いまここ
tier: max(6L×768) / standard(4L×512) / lite(4L×256) / deep-lite(6L×256, 実験)
```

## 前史: アルゴリズム期〜教師モデル

- 格子+辞書コストのみの変換器を先に完成(recall@200=100%)。以後一貫して
  「モデルは辞書コストとブレンドする再ランカー」であり、単独の変換器ではない。
- LINE DistilBERT cross-encoder を Sonnet生成の対照データでPDCA 5周:
  dev top1 74.65→79.65%、locked(276) 81.52%。辞書重みグリッドはこの頃から(0.35→0.75)。
- その後、教師を LUW BERT cross-encoder(現 warabi-reranker-v1、MeCab+SentencePiece)に移行。
  ブレンド重みの単純化(`blend = ai_logit - w * calibrated_cost / 1000`)もこの期に確立し、
  以後**スコア融合アルゴリズムは不変**(モデルの欠陥は蒸留データで直す原則)。

## 蒸留期(v1〜v5b): 教師を文字レベル生徒に移す

- 生徒は全tier DistilBERT・**文字レベルトークナイザ**(1文字=1トークン、正規化なし、
  MeCab非依存 — Rustランタイムの要件)。
- KD損失: `0.2·CE + 0.5·T²·KL(T=2) + 0.3·MSE`。教師logitsはサイドカーにキャッシュ
  (**トークナイザ非依存なので世代をまたいで再利用可** — 後々効いた設計)。
- **教師移植初期化**(教師のトランクをコピー)で max が locked 81.9% と**教師(80.8%)超え**。
  蒸留は「劣化コピー」ではなく正則化として働く、が最初の大きな学び。

## v6/v6b: 未知語判定能力の蒸留

- 症状: 生徒は「うまるちゃん」を漢字に無理変換(産まるちゃん)。教師は未知語を未知語と
  判定できる。原因は学習データがほぼ全行文脈付きで「単語らしさ」を学ぶ機会がないこと。
- 対策=**空文脈KD**(noctx): 文脈を剥がした行を教師に採点させ混ぜる。+合成データ
  (compose/suffix)。副作用事故: MeCabが顔文字を細切れにするため教師が合成行の顔文字に
  高評価→生徒が「顔文字合成クラス」を学習。合成行からの顔文字候補除外で修正
  (**noteの自然行からは除外しない** — しょぼーん→顔文字の学習源のため)。
- v6b: 同音異義語ベンチ39ケースで **39/39**(v5bは35/39)。

## ランタイム移行: Burn → ONNX Runtime

- Burn(wgpu)はデスクトップで健闘(13.7ms/フォワード)もAndroidで6.2s(カーネル未成熟)。
- ort実測: S24実機CPU 54ms、デスクトップCPU 12.5ms/フォワード → **全プラットフォームort統一**。
  torch学習→ONNXエクスポート(opset17、実測ドリフト~1e-5)→ロード時パリティゲート。
- パリティゲートは後に**バッチ再生検査**を追加(XNNPACK EPが「単発は正しくバッチで嘘をつく」
  故障で発覚)。以後、壊れたEPはロード時に綺麗に弾かれる。

## v7(文節世代): 分布を実入力に合わせる

- 洞察(ユーザー): 実際のIME入力は「名詞+助詞ごと」の文節粒度。学習データは単語粒度だった。
- note記事から**文節マイニング**(内容語+後続助詞/助動詞を結合、固有名詞頭は除外=評価専用原則)
  30万行。全キャッシュ再生成(格子顔文字ポリシー反映=学習分布と実行時分布が初めて一致)。
- 結果: dev top1 82.96%、同音異義語39/39維持、うまるちゃん#1回復。
  旧基準(1回きりの例外測定): locked 80.4%(-1.1 — 旧セット過適合の剥がれ)、
  **curated 80.8%(+5.9)** — 文節データは広い分布で汎化した。
- 認定重み w=0.08(文節devは辞書コストに単調)。

## v8(語彙世代): 目隠しを外す

- 旧vocab(8,192)はv1期コーパスで構築され、note導入・絵文字保持辞書化の後に再検証されて
  いなかった(natural UNK 0.027%→0.55%に劣化。**「アルゴリズム生成物は前提が変わるたび実測」
  の教訓の発火点**)。
- 新vocab 16,384: 現8,192全保持∪追加8,192(辞書+コーパスの漢字全部=13,882字、顔文字構成字
  1,024=完全可視98%、絵文字483=出現97.5%、半角全角/旧かな/数学記号完備)。コードポイント順で
  人間可読。選定規則:「①かな+ASCII保証 ②頻出記号・顔文字・絵文字 ③残枠すべて漢字(頻度順)」。
- **恒等拡張**(ime-extend-vocab): 並び替え=置換をembedding行に追従させ、新行は[UNK]コピー
  → 拡張直後のモデルは数学的に旧モデルと同一(drift 0.0)。**学習し直しゼロで語彙倍増**。
  継続学習2ep(教師logits再利用、note全量396k行に増量=アトラクタ語対策)。
- max-v8: dev 83.16%、ブレンド86.03%(w=0.05)、同音異義語38/39(詠む/読むはマージン0.4の
  ノイズ圏)、アトラクタ11/14(はしを|わたる→和 を修復)。絵文字入り文脈の読解が可能に。
  実メモリ+36MB(max)/+10MB(lite)、推論速度影響ゼロ(実測)。
- 判明した分業: **絵文字同士の順位はUNK盲目のまま辞書コスト(将来パーソナライズ)が担当**で
  正しい。モデルの役目は文脈読解と「候補が場に合うか」まで。

## tier実験: 幅か深さか教師か

| tier | 構成 | dev top1 | ブレンド | 同音異義語 | 実機(S24) |
|---|---|---:|---:|---:|---:|
| lite-v7 | 4L×256 (5.3M) | 83.59% | 85.75% | 32/39 | 33ms |
| **lite-v8** | 4L×256 (7.4M) | **84.03%** | **85.99%** | **36/39** | 32〜41ms |
| std-v8 | 4L×512 (21M) | 84.42% | 85.88% | 33/39 | 136〜286ms |
| max-v8 | 6L×768 (55M) | 83.16% | 86.03% | 38/39 | 433〜553ms |
| deep-lite | 6L×256 (7.9M) | (実験中) | — | — | — |

- lite-c1(旧世代教師・旧分布)は「アルゴリズム以下」の惨状(公園会、い状が見つかった)
  → 分布一致(v7)で32/39、**v8教師の再採点+継続学習で36/39**。教師信号の質が幅より効いた。
- stdはdevでは教師超え(84.4)だが同音異義語の尻尾は33 — **幅は知識量(dev)を買い、
  難問の文脈合成は買わない**。4層勢(32-33)vs 6層max(38)の断層から深さ説を検証中(deep-lite)。
- カスケード蒸留の生徒教師超えは再現性のある現象(v5b、std、lite-v8)。

## バックエンド実測

**デスクトップ**(Core Ultra 7 265K + RTX 5080 + Intel NPU):
- ort CPU: lite 13-60ms / max 116-474ms(32候補リランク全体)。GPU系(DirectML/CUDA/TRT/
  OpenVINO)は配線予定 — 小型モデルはGPU利得なし(Burn期実測: GPU 13.7 vs CPU 12.5ms)、
  maxクラスのみ価値。INT8はCPUでは逆効果(u16活性が非最適経路で+20%遅)。

**モバイル**(S24/SD8Gen3):
- CPUが最適解(NNAPI: liteで+10ms・maxで利得なし、初回形状+50%。XNNPACK: 動的バッチ破壊
  =ゲートで恒久棄却)。
- **QNN(Hexagon NPU)は凍結**: ロード・精度・正しさ全部OKだが実行が秒級
  (fp16=26s / w8a16=52s / a8w8=2.3s)。原因はグラフ分断(HTPはINT8の一枚岩グラフを要求、
  こちらは16bit活性・fp32島・-inf定数・LayerNorm断片という規格外の荷姿)。
  再開時: -inf→-10000のグラフ手術+全量a8w8+混合精度で精度回復+プロファイラで島数実測。
  量子化の知見: 全量量子化はドリフト6.6(-inf汚染ほか)、線形層+GELUのみなら0.02。
  Softmax量子化は入力の-infで即死。quantize_staticのnodes_to_excludeは前処理リネームで無効。

## 事故と教訓

| 事故 | 教訓 |
|---|---|
| vocab UNK劣化(20倍)に2世代気づかず | 生成物は前提が変わるたび実測で再検証。数千行なら全量目視 |
| v6顔文字合成クラス | 合成データは教師のノイズごと蒸留される。目視+ゼロ件チェック |
| XNNPACKバッチ崩壊でアプリクラッシュ | ゲートは実行時の形状クラスを網羅する(バッチ再生検査) |
| GPU学習が~80分周期でCUDA unknown error | 失速→死の前兆パターン。エポック末チェックポイントから再開 (v6b BSOD以来の定型)。温度ログ並走で切り分け |
| 実機UI自動化が「人の介助で動いているように見えた」 | 座標決め打ち禁止。毎回bounds解決+遷移検証(device-bench skill) |
| PS5.1のBOM無しUTF-8/非整数tap座標/NUL redirect | shellの流儀に従う。長い自動化はスクリプトファイル化 |
